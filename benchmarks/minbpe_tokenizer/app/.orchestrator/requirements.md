# Product
`minbpe`: a Python library (plus `train.py` script) implementing byte-level BPE tokenizers: `BasicTokenizer` and `RegexTokenizer` (GPT-4 split pattern, special tokens), with train/encode/decode/save/load.

# Acceptance criteria
R1. `Tokenizer` base class has `merges`, `vocab`, `special_tokens`, `pattern`; initial vocab is 256 single bytes.
R2. `train(text, vocab_size, verbose)` raises ValueError if vocab_size < 256; performs vocab_size-256 merges (stops early without error if no pairs remain, e.g. empty/short text); new ids 256+.
R3. Each step merges the most frequent adjacent pair counted over all chunks (weighted by chunk multiplicity); ties -> pair first occurring when scanning training data in order (chunk order, position within chunk).
R4. `vocab[new_id] == vocab[a] + vocab[b]`.
R5. `encode` greedily merges the eligible pair with lowest merge index until none left; works on empty string and single bytes.
R6. `decode(ids)` concatenates bytes (special tokens included), decodes UTF-8 `errors="replace"`; unknown id raises ValueError.
R7. `decode(encode(x)) == x` for any Unicode text (emoji, CJK, control chars, newlines), for both tokenizers.
R8. RegexTokenizer: default GPT-4 pattern (needs `regex`); custom pattern allowed; merges never cross chunk boundaries.
R9. `register_special_tokens(dict)`; `encode(text, allowed_special)`: "none_raise" (default; raises if text contains any special token string), "all", "none" (treated as ordinary text), or a set (subset; others as ordinary text... assumption: set must be subset of registered, else ValueError). `encode_ordinary(text)` ignores specials. decode maps special ids back to their strings.
R10. `save(prefix)` writes `<prefix>.model`: `minbpe v1`, pattern line (empty for Basic), count of special tokens, `<token> <id>` lines, then `<id1> <id2>` merge lines in order; and `<prefix>.vocab` human readable (token repr with `[a][b] -> [ab] id` for merges; invalid UTF-8 rendered with replacement char, control chars escaped).
R11. `load(model_file)` (must end in `.model`, version checked) restores merges, pattern, special tokens, vocab; encode/decode identical to original. Basic and Regex both.
R12. `train.py` trains both at vocab 512 on a text file (arg, default bundled `data/taylorswift.txt`-like sample generated deterministically? -> bundle `data/sample.txt` ~185kB of public-domain-style synthetic text), saves to `models/` as `basic` and `regex`, prints training time. Training 512 on ~185 kB < 30s.
R13. Training is efficient (incremental pair-count updates, not full recount per merge naively beyond reason).
R14. README, requirements.txt/pyproject, pytest tests.

# Assumptions
- Ties are broken by first occurrence, implemented by tracking first-occurrence index per pair.
- Basic tokenizer treats whole text as one chunk.
- Sample data is generated by a deterministic script (`data/make_sample.py`) from a built-in word list, to avoid network.
- Allowed_special set containing unregistered tokens -> ValueError.

# Test strategy
pytest: unit tests for R1-R9 (including hand-computed training example "aaabdaaabac", tie-breaking, brute-force reference implementation compared on random text), roundtrip fuzz (R7), save/load file-format tests (R10, R11), train.py subprocess test with small file (R12), speed test (R13).
