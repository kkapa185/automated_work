# LANG-54 — Lua 5.5 interpreter: requirements

## Product statement
A from-scratch, self-contained interpreter for the Lua 5.5 language and its standard libraries, written in
C11 (gcc/make, no third-party deps), run as `./lua [script [args]]` from the workspace root. The Lua 5.5
manual in `docs/manual.of` is normative. Pipeline: lexer -> parser producing an AST with compile-time scope
resolution (locals/upvalues/5.5 `global` declarations/`<const>`/`<close>`) -> tree-walking evaluator over
resolved slots, a conservative mark-and-sweep GC, `setjmp/longjmp` error handling, and `ucontext`-based
coroutines. The deliverables are the interpreter, a test-suite (`make test`) and a README.

## Acceptance criteria
### Core language
- R1  CLI: `./lua script.lua a b` runs the script; global `arg` has `arg[0]=script`, `arg[1]="a"`, `arg[2]="b"`, negative indices for interpreter; `...` in main chunk = a, b. No script => read program from stdin (or REPL-less: executes stdin). `-e`, `-` and `-v` are optional extras. `./lua` works from a clean checkout (launcher builds the binary via make when missing).
- R2  Uncaught error: stderr gets `lua: <message>` then `stack traceback:` + frames; exit status 1. Error objects that are non-strings without `__tostring` print `lua: (error object is a table value)`. Syntax errors: `lua: file:line: message near 'tok'`, exit 1. Normal end exit 0; `os.exit(n|true|false)` sets status.
- R3  Value types nil, boolean, integer (64-bit wraparound), float, string (arbitrary bytes incl. `\0`), table, function, coroutine (thread), userdata (file handles). `type()` names correct. `math.type`.
- R4  Lexer: short/long strings (`[==[ ]==]`, first newline skipped), long comments, escapes `\a\b\f\n\r\t\v\\\"\'`, `\ddd`, `\xXX`, `\z`, `\u{XXX}` (up to 2^31), line continuation `\<newline>`; numerals decimal/hex ints, floats, exponents, hex floats (`0x1p4`, `0x.8`), integer overflow of decimal literal => float, hex integers wrap modulo 2^64; comments `--`; shebang first line skipped; errors for malformed numbers/unfinished strings with line numbers.
- R5  Operators and precedence exactly per manual §3.4.8 (`or < and < comparison < | < ~ < & < shift < .. (right) < +- < */ // % < unary < ^ (right)`); `//` floor division and `%` floor modulo for ints and floats (incl. by zero: int => error "attempt to perform 'n//0'" / "attempt to perform 'n%0'", float => inf/nan), `/` and `^` always float, bitwise ops on ints (floats with exact int value convert; else error "number has no integer representation"), shifts >=64 give 0, negative shifts reverse, `..` on strings/numbers, `#` strings/tables (+`__len`), unary `-`, `not`, `~`.
- R6  Number<->string conversions: float formatting `%.14g` with `.0` appended when it looks like an integer (`1e15`->`1e+15`, `2^53`->`9.007199254741e+15`, `3.0`->`3.0`, `-0.0`->`-0.0`, `inf`, `-inf`, `nan`/`-nan`); string->number coercion in arithmetic (`"10"+1 == 11`, `"0x10"+0 == 16`, `"3.0"+1 == 4.0`), `tonumber` (bases 2..36, whitespace, hex floats, rejects trailing garbage), integer/float comparison exact (`math.maxinteger + 0.0 == 2^63`, `1 == 1.0`), float keys normalised to ints (`t[1.0]` is `t[1]`), NaN key error, nil key error.
- R7  Statements: `local`/assignment (multiple, evaluation order: all RHS before assignment), `if/elseif/else`, `while`, `repeat ... until` (until-condition sees body locals), numeric `for` (int loop without overflow, float loop, step 0 error "'for' step is zero", non-number errors "'for' initial value must be a number"), generic `for` (4 values in 5.5: iterator, state, control, closing value), `break`, `goto`/labels (continue-style, nested, rules: no jump into scope of a local; "no visible label" error), `do ... end`, `return` (multiple), function call statements, method calls `a:b()`, `function a.b.c:m()`.
- R8  Local/global declarations per Lua 5.5: `local x <const>`, `local x <close>`, `global x, y`, `global x = v` (error if already defined — non-nil), `global function f`, `global <const> *`, `global *`; implicit initial `global *`, voided inside scope of any other `global` declaration (then undeclared names give compile error `variable 'X' not declared`); assignment to const gives compile error `attempt to assign to const variable 'x'`; for-loop control variables are read-only; `<close>` variables call `__close(value, err)` on scope exit by normal end, break, goto, return and error, in reverse order; value must have `__close` or be nil/false else error "variable 'x' got a non-closable value"; at most one tbc var per list.
- R9  Functions: closures with shared/fresh upvalues per loop iteration, varargs `...` (`select('#')`, `select(-1,...)`, `table.pack`), multiple results adjusted properly (truncation in parens, expansion only in last position), proper tail calls (1e6-deep tail recursion works in constant stack), deep non-tail recursion (depth >= 150000... at least 100000 simple frames) works and runaway recursion raises catchable `stack overflow` error rather than crashing.
- R10 Metatables & metamethods: `__index` (function/table chains), `__newindex`, `__call` (chains), `__eq` (only for same-type tables/userdata), `__lt`, `__le`, `__concat`, `__len`, `__unm`, `__bnot`, `__add __sub __mul __div __mod __pow __idiv __band __bor __bxor __shl __shr`, `__close`, `__gc` accepted (no-op), `__mode` accepted (ignored), `__name` (used in error messages/tostring), `__tostring` (and error if it returns non-string), `__pairs`, `__metatable` (getmetatable returns it; setmetatable errors "cannot change a protected metatable"), `__idiv`... String metatable with `__index=string` so `("x"):rep(3)` and `s:upper()` work.
- R11 Errors: `error(msg, level)` adds `chunk:line:` position for string messages at level 1 (default), level 2 = caller, 0 = none; non-string error values pass through unchanged; `pcall`/`xpcall` (handler receives original value, handler called at error point so `debug.traceback` works) return `false, err`; `error()` with nil; error through coroutine boundaries; runtime messages with variable info: `attempt to index a nil value (local 'x')`, `(global 'x')`, `(field 'x')`, `(upvalue 'x')`, `(method 'm')`, `attempt to call a nil value (global 'f')`, `attempt to perform arithmetic on a nil value (field 'y')`, `attempt to concatenate a table value (local 't')`, `attempt to compare number with nil`, `attempt to compare two table values`, `number has no integer representation`, `attempt to get length of a number value`; messages carry `chunkname:line:` where chunkname for files is the script name as given (`script.lua`), for `load` strings `[string "first line..."]`. `assert(false)` => "assertion failed!", `assert(false,msg)` passes msg (any type) unchanged.
- R12 Coroutines: `create, resume, yield, status, wrap, isyieldable, running, close`; values pass both ways; yield across pcall, metamethods, iterators, `table.sort` comparators etc.; status `suspended/running/normal/dead`; resume dead => `false, "cannot resume dead coroutine"`; wrap propagates errors (with position prepended if string); `coroutine.close` runs pending `<close>` vars and returns `true` or `false, err`; yield outside coroutine => error "attempt to yield from outside a coroutine"; thousands of coroutines can be created (GC reclaims their stacks).
- R13 Memory: automatic garbage collection (mark & sweep) so that loops creating 1e7 short strings/tables, or `s = s .. "x"` 1e5 times, run in bounded memory; `collectgarbage("collect")`, `"count"` (KB float), `"step"`, `"isrunning"`, `"incremental"`, `"generational"`, `"stop"`, `"restart"`, `"setpause"`, `"setstepmul"` accepted with sensible return values.

### Standard library
- R14 Base: `print` (uses `__tostring`/`__name`), `type, tostring, tonumber, pairs (with __pairs), ipairs (respects __index), next, select (negative too; error "bad argument #1 to 'select' (index out of range)"), rawget/rawset/rawequal/rawlen, setmetatable/getmetatable, assert, error, pcall, xpcall (extra args), load (string or function chunk source, chunkname, mode, env; returns nil,msg on syntax error), loadstring-free, dofile, loadfile, require, collectgarbage, _G, _VERSION == "Lua 5.5"`. Argument errors use the form `bad argument #n to 'fname' (number expected, got nil)` ; `got no value` when missing.
- R15 `string`: `len sub upper lower rep(with sep) reverse byte char format find match gmatch gsub pack unpack packsize`; negative/out-of-range index rules; full Lua patterns (`. %a %c %d %g %l %p %s %u %w %x`, complements, sets/ranges, `* + - ?`, anchors, captures incl. position captures `()`, back-references `%1`, `%b()`, `%f[set]`, gsub with string (`%0-%9`, `%%`)/table/function replacement, anchored gmatch (init arg), `find` with plain flag and init); error messages "malformed pattern (ends with '%')", "invalid pattern capture", "invalid capture index %1", "missing '[' ..."; pattern matching must not recurse unboundedly for long subjects with simple `.-`/`.*` (no C stack overflow on 1e6-char subject); `format`: `%d %i %u %c %x %X %o %e %E %f %F %g %G %a %A %s %q %%` with flags/width/precision, `%s` uses `tostring` semantic (`__tostring`), `%d` with float that has int value ok else error "number has no integer representation", `%q` round-trippable; `pack/unpack/packsize` with all options (`< > = ! b B h H i[n] I[n] l L j J T f d n s[n] z x X ' '`), alignment.
- R16 `table`: `insert` (position checks "bad argument #2 to 'insert' (position out of bounds)"), `remove`, `concat` (error on invalid value "invalid value (at index 1) in table for 'concat'"), `sort` (comparator; "invalid order function for sorting" tolerated; O(n log n), must sort 1e5 elements fast), `unpack` (with ranges), `pack` (field `n`), `move`; respect `__index/__newindex/__len` metamethods.
- R17 `math`: `abs ceil floor sqrt sin cos tan asin acos atan(y,x) exp log(x,base) pow-free fmod modf huge pi maxinteger mininteger tointeger type ult max min random randomseed` (`random(m,n)` ranges/ errors "interval is empty", `random(0)` random integer, float in [0,1)); `floor/ceil` return integers when representable; `fmod` int semantics and error "bad argument #2 to 'fmod' (zero)"; `modf` returns float parts (`3.0  0.5`, inf handling), `abs(mininteger)` wraps.
- R18 `utf8`: `char charpattern codepoint codes len offset` with lax flag, error messages ("invalid UTF-8 code").
- R19 `os`: `time` (with table, normalises fields), `clock`, `date` (formats `*t`, `!*t`, strftime conversions), `getenv`, `exit`, `remove`, `rename`, `tmpname`, `difftime`, `setlocale` (stub returns "C").
- R20 `io`: `write`, `read` (formats `n l L a` and counts, with "*" prefixes tolerated), `lines`, `open` (modes r w a r+ w+ a+ b), `close`, `input/output`, `stdout/stderr/stdin`, `type`, `tmpfile`, `popen` (optional), file methods `read write lines close seek flush setvbuf`, `__tostring` "file (0x...)" / "file (closed)", `__name="FILE*"`, `__gc/__close`; `io.write` returns file for chaining; errors return `nil, msg, errno`.
- R21 `require`/`package`: `package.path` (default includes `./?.lua`), `package.loaded`, `package.preload`, `package.searchers`, `package.searchpath`, `package.cpath` (string only), `require` returns module value and loader data, caches, error message listing tried paths "module 'x' not found:..."; `dofile`, `loadfile`.
- R22 `debug` (minimal): `traceback([thread,] [msg [, level]])`, `getinfo` (fields `currentline, short_src, source, what, name, func, linedefined`), `sethook` no-op, `getlocal` limited, `getmetatable/setmetatable`, `upvalueid`-free. Enough for common test usage.

### Quality
- R23 Performance: `fib(25)` recursive < 1s typical (limit 5s), `for i=1,1e6` accumulation loop < 1s, 1e6 table inserts/gets < 2s, string building and sorting 1e5 numbers < 2s, string.rep/concat of 1e6-1e7 bytes fine. Benchmark tests assert time limits generously (tests in `tests/bench`).
- R24 Test-suite: `make test` (also `tests/run.sh`) builds the interpreter and runs every `tests/cases/*.lua` (self-checking with `assert`, or with an `.expected` stdout file), plus CLI tests (exit codes, stderr format, `arg`), plus benchmark tests. Every example in the manual's text for the areas above that has an explicit result comment is covered.
- R25 README documents what it is, build (`make`), run, test, architecture/design, limitations (no `string.dump`, no C API, `__gc`/`__mode` no-ops, locale "C").
- R26 Robustness: interpreter never segfaults on bad input (deep nesting of parser: "chunk has too many syntax levels" / C levels overflow reported as error; very long string concatenation chains; huge `string.rep` => "resulting string too large"; invalid UTF-8 in source ok).

## Assumptions
- A1 Implementation language C (fastest option available: gcc 13 present). Built with `-O2`; `ucontext` (glibc) available. 64-bit Linux only.
- A2 `./lua` is a small POSIX shell launcher that runs `make -s` if `bin/luai` is missing/outdated and then `exec`s it; `make` at workspace root also produces `bin/luai`.
- A3 GC is conservative for the C stack (mark & sweep, exact for heap objects); `__gc` finalizers never called, weak tables stay strong; `collectgarbage("count")` reports bytes allocated in GC objects.
- A4 `string.dump` unsupported (raises "unable to dump given function"); `load` accepts text chunks only (mode "b" fails with "attempt to load a text chunk (mode is 'b')").
- A5 Number-for-loop and generic-for follow Lua 5.5 semantics (control variable read-only; generic for has closing value 4th slot).
- A6 Where the manual leaves messages unspecified I follow the familiar Lua 5.4 message texts; tests assert on stable substrings.
- A7 `-nan` vs `nan`: printed using the C library `%.14g`, as in standard builds on Linux.
- A8 (printf-escaped in the C source, so a single % is printed) Integer division/modulo by zero messages: "attempt to perform 'n//0'" and "attempt to perform 'n%0'".
- A9 `#t` border: any border allowed; implementation returns array-part length / binary search in hash.
- A10 Coroutine C stacks are 1 MiB lazily-committed `mmap`s; recursion in a coroutine is limited by stack-pointer check (error "stack overflow"); main interpreter runs on a large (up to 1 GiB virtual) stack with Lua call depth limit of 200000.

## Test strategy
- Unit-ish Lua scripts per area under `tests/cases/` (lexer, operators, numbers, strings, patterns, format, pack, tables, metatables, closures, goto, close/global (R8), errors/messages, coroutines, gc stress, libs) using `assert`; expected values derived by hand from the manual (not from the implementation).
- `tests/cli/*.sh`: exit codes, stderr/traceback format, `arg`, syntax-error format, stdin script (R1, R2).
- `tests/bench/*.lua` with `os.clock` assertions (R23, R13, R15 patterns, R16 sort).
- Manual examples: `tests/cases/manual_examples.lua`.
- Runner `tests/run.sh` prints per-file PASS/FAIL, non-zero exit on any failure.

## Assumptions added during M1
- A11 `error()` / `error(nil)` uncaught prints `lua: (error object is a nil value)`; non-string error objects without `__tostring` print `(error object is a <type> value)` without traceback.
- A12 Parser nesting limit is 190 syntax levels (message `chunk has too many syntax levels`); `a..b..c` chains are parsed iteratively and are not limited.
- A13 Parse errors for EOF use `near <eof>` (unquoted); lexical errors quote the partial token (`near ''abc'`).
- A14 Until the later milestones land, `open_string/table/math/os/io/utf8/coroutine/debug/package` are empty placeholders in `src/stubs.c`.
- A15 (M2) Coroutine stacks are 8 MiB lazily-committed mmaps (fallback 1 MiB); context switch is a custom x86-64 routine (Linux x86-64 only). On an erroring coroutine, pending `<close>` variables stay pending until `coroutine.close` (or the `wrap` error path) runs them, as in the reference semantics.
- A16 (M4) `pairs(x)` does not type-check `x` (only `next` does, reporting `bad argument #1 to 'for iterator'`); `ipairs`/`pairs` without arguments report `value expected`. `debug.getlocal`/`sethook` are inert; `package.loadlib` reports that dynamic libraries are unavailable. `os.date` uses the C library `strftime` after validating the conversion specifier.
- A17 (M5) `<close>` metamethods receive only the value when no error is in flight (manual §3.3.8) and `(value, err)` otherwise; only the first generic-`for` variable is read-only. `load` with a failing reader function returns `nil, err`. The GC does not treat the per-thread return buffers as roots (collections only occur at safe points where no results are in flight). Argument lists / `table.unpack` results that would not fit on the current C stack raise `stack overflow` / `too many results to unpack`.
